# Server

- `src/server.ts` reads `NODE_ENV`, the host, the port and the grace delay with its own `Config` program, before the Runtime exists, because `NODE_ENV` picks Fastify's logger and the application Layer needs that logger. It also reads the settings of the `.well-known` files and passes them to the application plugin, so Fastify's routes stay plain. It's the one exception to the root's rule that each Layer reads its own settings, so read every other setting in the Layer that needs it.
- Write every API endpoint as a tRPC procedure in `packages/api`, so the mobile app gets its types from the router. Add a Fastify route only for what tRPC can't serve, such as better-auth's handler or a `.well-known` file.
- Inside a request, log with `request.log`, or with Effect's logging functions, such as `Effect.log`, in an Effect program, so every line carries the request ID ([Fastify](https://fastify.dev/docs/latest/Reference/Logging/)). Use `server.log` only outside a request.
- To fail a route, throw an error with a `statusCode`, and build no error response in the route, because only the error handler and the not-found handler build them, in the shape that [Fastify's errors](https://fastify.dev/docs/latest/Reference/Errors/) describe, and the error handler hides the message of every error of 500 and above.
